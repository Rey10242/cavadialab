# Architecture and review rules
- Keep shared services, prices and homepage FAQs in `src/content/site.ts`; UI and schema consume the same source to prevent contradictory claims.
- Metadata is owned per route by `Seo`; static head is a truthful sitewide social fallback, with replaceable Helmet tags and no static canonical.
- Indexable routes own replaceable crawler directives through `Seo`; `NotFound` uses noindex for generic and named bots so invalid URLs do not inherit indexability, and returning to a valid page restores it.
- Keep one identity graph with stable Person/business/WebSite IDs; route graphs reference these IDs rather than inventing providers.
- GTM stays in the static entry document once; contact clicks are engagement, and only a successful stored form submission emits form success.
- Keep the Classic stack for this change; SSR requires the official gated in-place TanStack migration and a separate preflight, not ad-hoc prerendering.
- Keep Bun business-rule and measurement tests under `tests/`, outside the browser-only application typecheck; run them with `bun run test`.
- Keep readable-first-paint reveals and landing diagrams in `StudioVisuals`; effects never gate content.
- Use native anchor chapters for the homepage narrative and Radix accordions for FAQs; homepage FAQ UI and schema consume the same four-entry selection to prevent contradictory claims.
- Express the studio visual system through semantic global CSS tokens and a single principal sans family shared by home and landings for cohesive editorial rhythm.
- `AttentionJourney` owns the homepage hero visual: authentic cutout portrait with real platform logo pills highlighted by scroll chapter, plain HTML/CSS with no WebGL, because a person-led visual communicates trust faster than abstract 3D.
- Landings share one scan-first template in `LandingPage` (art + real tool pills, bento chips, steps, FAQ, CTA); per-service illustrations live in `src/assets/landing` as decorative webp, never presented as real work.
