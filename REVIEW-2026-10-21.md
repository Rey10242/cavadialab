# Cavadia Lab — review for owner / Claude

## Scope and decisions
- Existing Classic React/Vite project refined in place. No publishing, DNS changes, route removal, new project, framework migration, or production function deployment.
- Preserved authentic portrait, navy/orange identity, cavadialab.com, GTM container, WhatsApp, email and social links.
- Personal brand connects advertising, measurement and web technology. Hospitality is highlighted without adding client names, case studies or numerical evidence.
- Shared service/price/FAQ data prevents conflicting UI and schema. COP 130000 session / COP 440000 pack retained; USD equivalents removed.
- Unsupported experience counts, rating of 50 reviews, credentials, SearchAction and global hreflang removed. Dormant fabricated testimonial/case-study source files removed too.
- Country pages kept indexable, differentiated honestly as remote service from Cartagena. Currency, language, scheduling and legal conditions are agreed, not asserted as proven operations.
- No hreflang: these pages target distinct projects/markets and are not verified translations of the same content.
- Static HTML has truthful sitewide social metadata. Helmet owns self-referencing absolute canonicals, page metadata and one identity/page graph after rendering. Old OG asset is not tagged: its historical wording no longer matches the offer. No new share asset fabricated.
- Broken source-image preload removed. Portrait has explicit intrinsic dimensions and priority; no above-fold lazy loading. No extra GTM loader introduced.
- Click events are engagement, not confirmed leads. Successful stored request emits `contact_submission_saved`, not a sale. Notifications are described separately from storage and delivery is never claimed from an accepted request alone.

## Real pending items / boundaries
- **SSR:** current project is Classic React/Vite/BrowserRouter, suitable in shape for the official migration. Formal eligibility is only established by its gated preflight, not this source audit. Use Lovable's official in-place “Migrate to TanStack Start” flow separately; it checks eligibility and a green baseline, ports theme/head/GTM/Cloud integration and verifies SSR. No migration lifecycle started here. Current per-route metadata is client-rendered; non-JS social crawlers get sitewide fallback, not accurate individual page previews.
- **Email delivery:** not tested externally. Existing `notify-contact` function interpolates submitted fields into HTML and returns provider data; input validation, escaping and minimal response/logging warrant a separate function-security correction. No function deployed in this preview-only change. UI now checks provider error/id instead of trusting `success` alone, and never claims inbox delivery.
- **Analytics delivery/configuration:** local event payloads verified; GTM workspace tags, GA4 receipt/deduplication, consent/legal setup and conversion configuration not accessed or certified. Existing container may have its own configuration outside source.
- **Owner evidence:** achievements, credentials, client consent, case studies, operational currencies and legal compliance remain unvalidated and are not advertised as proven.
- **Search/live:** no publishing or live crawler rescan performed; rankings, indexing, favicon appearance in search engines and lead generation cannot be guaranteed. Favicon references corrected to actual file dimensions; browser/tab/search display depends on browser and crawler fetches.
